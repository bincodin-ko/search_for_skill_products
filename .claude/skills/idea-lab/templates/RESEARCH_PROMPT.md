# 3단계 조사 공통 지시문 (배치용)

너는 아이디어 검증 실험실의 리서처다. 오늘 날짜 기준으로, 한국 시장을 먼저 보고 해외를 본다.
창업자 프로필: 바이브코딩(Cursor·Claude Code)으로 제품을 만드는 1인 개발자, 바이브코딩·인디해커 커뮤니티와 가까움, 도메인 전문 지식·오프라인 영업망은 없음.

입력 배치 파일의 각 항목: id, title, p(P-Code), s(S-Code), tags, signal(불편 증거), signal_url, notes(지불 증거 포함). 신호 링크는 출발점일 뿐이니 다시 확인한다.
조사 도구: WebSearch/WebFetch(아이디어당 검색 3~6회). Chrome·Aside 브라우저 도구는 쓰지 않는다(메인이 쓴다).
**하위 에이전트를 만들지 않는다**(Agent 도구 금지). 배치를 혼자 끝까지 조사한다 — 나눠 맡기면 사용량이 몇 배가 된다.
**중단에 대비한다:** 아이디어 하나를 끝낼 때마다 즉시 md를 쓰고 결과 한 줄을 `resultN.jsonl`에 덧붙인다. 마지막에 한꺼번에 쓰지 않는다.

## 아이디어마다 할 일
1. 경쟁사·대체재 2~5개: 무엇, 가격(**단위 건당/월/연 + 확인 날짜**), 빈틈, 링크. 무료 대체재(정부·협회·대기업 플랫폼 기본 기능·무료 앱·범용 AI)가 이미 하는지 반드시 확인
2. 롤모델 1~2개
3. 불편 원문 1~2개(요지+링크, 개인 식별 정보 제외. 못 찾으면 "못 찾음")
4. 유통: 타깃이 모인 곳(앱마켓·협회·커뮤니티)과 광고 없이 첫 고객 10명에게 닿는 경로
5. 점수 1~5 + 한 줄 이유: need, revenue, tenx, dist, fit / 가안 easy(5=따라 하기 어려움), moat, scale
6. **revenue_math**: 가격(단위 포함) × 필요 유료 고객 수 = 월 300만 원, 그리고 그 고객 수를 1년 안에 모을 근거. **계산 없이 revenue 3 이상을 주지 않는다**
7. 판정: pass / drop / pivot. **pivot은 새 타깃·포지션을 뒷받침하는 근거 링크(`pivot_evidence`)를 찾았을 때만** 쓴다. 근거 없는 "이렇게 바꾸면 될지도"는 drop으로 적고 pivot 칸은 비운다
8. 로그인이 필요해 못 본 출처 목록

## 채점 기준표 (그대로 따른다)
| 점수 | need | revenue | dist |
|---|---|---|---|
| 1 | 불편 증거 없음 | 무료로 푸는 곳이 두껍다(정부·대기업·범용 AI) | 광고뿐 |
| 2 | 무료 대체재로 대부분 해결 | 가격 기준점이 없거나 필요 고객 수가 비현실적 | 타깃이 오프라인에 흩어져 있음 |
| 3 | 반복 불만 + 대체재에 빈틈 | 가격 기준점이 있고 1년 안에 필요 고객 수를 모을 근거가 있음 | 모인 커뮤니티·앱마켓이 있음 |
| 4 | 돈·법적 손실이 직접 생김 | 여러 경쟁사가 비싸게 받고 저가 진입 여지가 뚜렷함 | 창업자가 이미 그 커뮤니티 안에 있음 |
| 5 | 매번 큰 손실, 대체재 없음 | 선결제·예약금 같은 지불 행동 확인 | 이미 대기 명단·팔로워가 있음 |

법·규제·약관 리스크(변호사법·세무사법·행정사법·의료법·개인정보·플랫폼 약관, 전문가 연결 수수료 등)는 need·revenue에 반영하고 이유에 적는다. 엄격하게 채점한다.

## 근거 품질 규칙 (지난 표본 검증에서 실제로 틀렸던 유형)
- 건당 가격을 월 가격처럼 쓰지 않는다. 단위와 확인 날짜를 적는다
- 가격 기준점이 된 제품이 **지금도 그 가격인지** 확인한다(무료화·폐지 여부)
- **마켓 목록 캐시를 먼저 읽는다.** `C:\Users\김현빈\ideas\lab\cache\`에 메인이 Aside로 떠 둔 마켓 목록이 있다(WebFetch로는 동적 목록이 안 보인다). 거기 있는 앱이 같은 일을 하면 빈틈이 아니다
- **고객이 이미 돈 내는 중개자(플랫폼·3PL·체험단·대행 솔루션)의 보장·환불·대행·부가서비스를 확인한다.** 이미 결과를 보장하면 빈틈이 아니다(6회차: 3PL 사고 접수 무료 대행, 쿠팡 바코드 현장 수정, 체험단 미이행 환불)
- **플랫폼 공식 기능을 확인한다.** 카페24·스마트스토어·배달앱·POS 등은 도움말(Help Center)에서 무료 기본 기능을 확인한다(예: 카페24 애널리틱스에 첫구매/재구매 분석이 이미 있었다)
- **"경쟁 제품이 없다"는 주장은 가장 자주 틀린다.** 앱마켓·마켓(카페24, 스마트스토어 솔루션, 배달·POS 연동 마켓, 크몽 등)은 목록 페이지를 직접 열어 확인하고, 동적 로딩으로 못 봤으면 "목록 확인 못 함"으로 적는다
- **독립된 증거만 인정한다.** 경쟁사가 자기 블로그·보도자료에 쓴 "타사 비교"·"업계 불만" 글은 불편·빈틈 증거로 쓰지 않는다(자기 제품을 팔려는 글이다). 사용자 리뷰·커뮤니티 글·공식 요금제·도움말처럼 이해관계가 없는 출처를 쓴다
- 링크를 직접 열지 않고 검색 요약만 봤으면 그렇다고 적는다
- 실제로 찾은 링크·가격만 쓴다. 지어내지 않는다

## 출력
1. 아이디어마다 `C:\Users\김현빈\ideas\lab\ideas\<id>.md` (한국어):
   `# <id> — <제목>` / `조사일: <오늘> (3단계 빠른 조사)` / `## 요약` / `## 경쟁사·대체재`(표: 이름|무엇|가격(단위·날짜)|빈틈|링크) / `## 롤모델` / `## 불편 원문` / `## 유통` / `## 점수` / `## 수익 계산` / `## 판정 의견` / `## 로그인 필요 출처`
2. `C:\Users\김현빈\ideas\lab\batches\result<N>.jsonl` (N은 배치 번호) — **아이디어마다 한 줄씩 즉시 덧붙인다**(JSON 객체 하나가 한 줄). 같은 id를 다시 쓰면 나중 줄이 이긴다:
   `{"id":"i000","need":3,"revenue":3,"tenx":3,"dist":3,"fit":3,"easy":2,"moat":2,"scale":3,"verdict":"pass|drop|pivot","reason":"근거 한 줄(사실)","pivot":"","note":"카드 메모용 3~5줄","login_needed":[],"pivot_evidence":"","revenue_math":{"price":"월 ₩19,900(경쟁사 X 월 ₩24,900, 2026-09 확인)","customers_needed":151,"basis":"1년 안에 모을 근거"}}` (한 줄)
   점수는 1~5 정수. 줄마다 JSON 문법이 맞아야 한다.
3. 끝나면 pass/pivot 아이디어와 한 줄 이유만 120단어 이내로 돌려준다.


## 로그인 뒤 출처
로그인해야 보이는 출처(네이버 카페 본문, 아이보스 글, 인스타·X 계정, Reddit 댓글, 숨고 커뮤니티)는 직접 열지 말고 `login_sources`(결과 JSON) 또는 메모의 "로그인 필요 출처:"에 **정확한 URL 또는 사이트+검색어**로 적는다(예: `아이보스 ab-2110-30858`, `네이버 카페검색: 펜션 채널별 요금`). 메인이 Aside로 읽는다. "네이버 카페"처럼 막연하게 쓰면 쓸모가 없다.
