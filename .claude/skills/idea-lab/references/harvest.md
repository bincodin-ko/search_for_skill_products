# 1단계 발굴 — 신호 하베스트와 사전 필터

머릿속에서 후보를 만들지 않는다(실측: 브레인스토밍 92개 중 90% Drop). 신호 종류별 **하베스터 에이전트**를 보내 후보를 모아 온다. 하베스터 공통 지시문은 `lab/batches/HARVEST_PROMPT.md`(원본: `templates/HARVEST_PROMPT.md`).

## 후보 하나에 증거 세 개
- **불편 증거 `signal`**: 반복 불만·의무·수작업
- **지불 증거 `pay_signal`**: 같은 타깃이 지금 이 문제에 돈을 내고 있다(대행·유료 도구·인건비, 가격 단위·날짜)
- **빈틈 증거 `gap_signal`**: 그 돈을 받는 기존 제품의 구체적 빈틈(독립 리뷰의 반복 불만, 3배 이상 비쌈, 특정 세그먼트 미지원, 마켓 목록에서 확인한 기능 부재). 플랫폼 공식 무료 기능도 도움말에서 확인한다
- 셋 중 하나라도 없으면 후보로 만들지 않는다. 경쟁사 자사 블로그의 "타사 비교"는 증거가 아니다

실측 근거: 불편만 모은 바퀴 통과율 약 5%, 지불 증거를 더한 바퀴도 약 6%(지불 증거가 곧 강한 경쟁자의 증거였다). 통과한 것은 모두 빈틈이 확인된 경우였다.

## 하베스트 운영
1. **마켓 목록이 조사원에게 보이는지 먼저 확인한다.** WebFetch로 목록이 나오면(예: apps.shopify.com, chromewebstore) 그대로 쓰고, 동적 로딩으로 안 보이면(예: 카페24 앱스토어) 메인이 Aside(`mcp__aside__repl`)로 관련 키워드 목록을 떠서 `lab/cache/<마켓>_<키워드>_<날짜>.txt`에 저장한다. 실측: 카페24에서 하베스터의 "빈틈" 8개 중 5개에 경쟁 앱이 있었고, i386은 조사까지 통과한 뒤 월 5,000원대 앱 4개가 발견돼 떨어졌다
2. `LAB stats --tags`로 고갈 분야(8개 이상 시도, 생존 0)를 `lab/batches/saturated.txt`에 적는다. 보드 목록은 `lab/batches/existing_titles.txt`(`id [stage] 제목`)로 뽑아 둔다
3. 하베스터는 **Sonnet**(`model: "sonnet"`), 동시 4명 이하, 목표 10~12개, 검색 약 40회 상한. 프롬프트에 "하위 에이전트를 만들지 않는다"를 직접 넣는다
4. 출력은 `lab/batches/<이름>.jsonl`(후보마다 한 줄 즉시), 메인은 끝난 것부터 `LAB import`
   - `prefilter: "hold: <볼 곳>"` 후보는 1단계에 `[보류]`로 남는다. 실측: B2B 틈새는 검색에 걸리는 글 대부분이 업체 자사 블로그라 독립 증거가 로그인·앱 리뷰 뒤에 있었다(덜 판 업종 하베스터 45회 검색에 후보 1개). 메인이 Aside로 그 출처를 열어 빈틈이 있으면 `LAB move <id> incubating`→`brainstorming`, 없으면 Drop
5. 태그의 업종은 `HARVEST_PROMPT.md`의 고정 목록에서만 고른다(고갈 지도가 흩어지지 않게)

## 선검증 (import 직후, 조사원을 보내기 전 — 메인)
**모든 후보**에 메인이 "<핵심 기능> 서비스/앱/프로그램" 검색 1번을 한다. 1페이지에 같은 일을 하는 제품이 무료·저가로 있으면 조사 없이 `LAB verify <id> --fail` + Drop.
- 실측(4회차): 조사까지 통과한 3단계 10개를 이 방식(후보당 검색 1번 + 의심 페이지 열기)으로 확인하니 7개가 이미 있는 제품이었다(아이로그·가격지키미·클라이원트·클린벨 파트너 등). 조사원 1명분 비용으로 검색 10번이면 된다
- 조사원이 놓치는 이유: 아이디어의 **이름**으로 찾고, 경쟁 제품은 **기능**으로 자기를 소개한다. 그래서 검색어는 제목이 아니라 "누가 + 무엇을 자동으로"로 만든다

마켓 기반 후보(앱스토어·확장·플러그인)는 추가로 조사원에게 보내기 전에 메인이 **후보마다 핵심 키워드 1개로 해당 마켓 검색 목록을 Aside로 떠서** `lab/cache/<마켓>_search_<날짜>.txt`에 추가한다(후보당 브라우저 호출 1번).
- 같은 일을 하는 앱이 무료·저가로 이미 있으면 조사 없이 `LAB move <id> dropped --reason "선검증: .."`
- 애매하면 캐시만 남기고 조사로 보낸다(조사원이 캐시를 읽는다)
- 실측(3회차): 조사원이 통과시킨 4개 중 3개가 표본 검증에서 틀렸다(Shopify 검색에 무료 관부가세 앱·배송보호 앱 15개 이상). 원인은 늘 "동적 검색 목록이 조사원에게 안 보임"이었다
- 어떤 페이지가 WebFetch로 보이는지: 카페24 앱스토어 검색 ✗(WebFetch) — Aside로 `store.cafe24.com/kr/search/apps?s=<검색어>` (keyword= 는 안 먹음), Shopify 카테고리 ✓·검색 ✗, 크롬 웹스토어 카테고리 ✓ — 안 보이는 곳만 Aside


**선검증 실수 세 가지(6회차 실측, 바로 고침)**
- 카페24 스토어 검색 결과를 페이지 끝부분만 읽어 시리얼 자동발송 앱을 놓쳤다(i607) → 결과 목록 **전체 제목**을 읽는다(`검색결과` 뒤 첫 1,500자 + '더보기' 페이지)
- 플랫폼이 직접 낸 AI 기능을 놓쳤다(i611 카카오모먼트AI 2025-12, i610 네이버 GFA AI 사전검수) → 광고·플랫폼 도구 후보는 **"<플랫폼> AI 신기능 2025 2026"** 검색을 선검증에 반드시 넣는다
- **고객이 이미 돈 내는 중개자가 결과를 보장·대행하는지 놓쳤다**(6회차 후반 3연속: i852 택배 배상 → 3PL이 사고 접수 무료 대행, i834 입고 회송 → 쿠팡이 바코드 현장 수정 부가서비스, i864 체험단 미이행 → 아싸뷰·강남맛집이 6개월 유지 의무·미이행 환불 보장) → 문제 바로 위·아래에 있는 중개자(플랫폼·3PL·체험단·대행 솔루션)의 **"보장·환불·대행·부가서비스"** 정책을 공식 FAQ에서 확인한다. 이미 보장하면 Drop(solved_free)

## 사전 필터 (조사 전에 1분, 하베스터도 적용)
걸리면 조사 없이 Drop(`prefilter: "drop: 이유"` 또는 `LAB move .. dropped --reason "사전 필터: .."`):
- 정부·공공기관 무료(고용24·홈택스·KIPRIS·나라장터 등) / 네이버·카카오·토스·통신사·OS·마켓 기본 기능
- 전문 자격 업무(변호사·법무사·노무사·세무사·행정사·의료·약사). 전문가 **연결 수수료**도 금지될 수 있다(변호사법 34조)
- (예외) 지불 증거가 없어도 **유명세 경로**(무료로 퍼져 광고·파생 제품·제휴·인수로 돈이 되는 길)가 보이면 버리지 않는다 — `fame_signal`에 비슷한 무료 제품의 규모와 수익 전환 선례를 적는다
- 범용 AI로 사용자가 직접 충분히 할 수 있는 일 / 평생 한두 번뿐인 일 / 대상 사이트 약관이 자동화·스크래핑을 금지
확실하지 않으면 통과시키고 리서처가 본다.


## 넓게 보기 — 편견 없는 시장 탐색 (6회차부터)
지금까지 후보는 "평범한 사장님 SaaS"에 몰려 고갈됐다. 하베스트 비중의 **최소 30%는 아래처럼 사람들이 잘 안 보는 시장**에 둔다. 낙인·민망함·비주류 때문에 경쟁자가 적고, 기존 도구가 이들을 거절하거나 무시하는 경우가 많다.

**합법이지만 외곽에 있는 시장(그레이 존)**
- 성인·나이트라이프: 성인용품점, 바·라운지·클럽, 나이트 행사, 성인 교육·상담(성 건강), 스트립이 아닌 합법 공연
- 죽음·종교·점술: 장례·유품정리·반려동물 장례, 무속·타로·사주 상담소, 사찰·교회 운영
- 중고·리셀·수집: 전당포·중고 명품 감정, 한정판 리셀, 수집품 경매, 고물상·재활용
- 사회에서 밀려난 사람들: 출소자·신용회복자·파산자 재기, 노숙·쪽방 지원 기관, 이주노동자·미등록이 아닌 체류 외국인, 성소수자, 장애인 당사자·가족
- 규제가 느슨하거나 새로 생긴 영역: 전자담배(합법 판매점), 대체육·발효, 반려동물 대체의학, 1인 방송 후원·팬덤 굿즈, 코스프레·서브컬처 행사, 성인 취미(타투·피어싱 스튜디오)
- 결제대행사·광고 플랫폼이 "고위험"으로 거절하는 합법 업종(여기엔 결제·광고 대체 수단이 곧 빈틈이다)

**평범하지만 안 본 시장** — 농어업·축산, 건설 하도급 말단, 공장 3교대 현장, 군·경·소방 가족, 종교 단체, 비영리·자원봉사, 고령 1인 가구, 해외 동포·유학생

**선 긋기(이건 넣지 않는다)**
- 한국 법상 불법이거나 불법을 돕는 것: 도박·사설 토토, 마약, 성매매·알선, 불법 대부·추심, 개인정보·계정 거래, 규제·단속 회피(과태료·세금·신원확인 우회), 사기·기만, 미성년자 대상 성인 서비스
- 사람을 해치거나 감시하는 것: 스토킹·몰래 추적, 아웃팅 위험을 키우는 설계
- 판단 기준: 대상 국가 법으로 합법 + 결제·호스팅이 가능한 경로가 있음 + 고객이 드러나도 해가 없음. 애매하면 `prefilter: "hold: 법 확인 — <조항>"`로 남기고 메인이 판단

**태도**: "이런 걸 누가 사?"라는 선입견으로 버리지 않는다. 불편·지불·빈틈 세 증거가 있으면 시장이 작거나 낯설어도 후보로 만든다. 판단은 3단계 점수와 관문이 한다.


## 생존 패턴 (6회차 실측 — 하베스터 비중을 여기에 맞춘다)
- 관문을 넘은 4개(i062·i332·i120·i140)의 공통점: **해외에선 유료 앱으로 검증된 기능 + 한국 플랫폼(카페24·스마트스토어·네이버 광고)이나 한국어 사용자에겐 없음 + 로그인 커뮤니티(셀러오션·아이보스·X)에 불편 원문**
- 플랫폼 정책 변경: **한국 플랫폼은 수율이 나온다**(네이버 2/17, 쿠팡·패션 2/16 → 선검증 후 i765 등), **해외 성숙 플랫폼은 0/20**(Helium10·PriceLabs 등 대형 도구가 변경 직후 대응)
