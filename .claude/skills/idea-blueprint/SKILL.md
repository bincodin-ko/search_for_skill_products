# idea-blueprint

아이디어를 **빨리 접거나, 바로 만들 수 있는 설계도로 바꾼다.** 결과는 `docs/blueprint/<slug>.md` 한 파일이다. 틀은 [template.md](template.md)를 따른다.

## 원칙

- **돈이 안 되거나 굳이 필요 없는 아이디어는 앞 단계에서 끝낸다.** 조사를 많이 한 뒤에 접으면 시간이 아깝다.
- 사실에는 출처 링크를 붙인다. 근거 없는 판단은 `[추정]`으로 표시한다. 수치를 지어내지 않는다.
- 사용자에게 묻는 건 두 번뿐이다: 시작할 때 빠진 정보(최대 3개), 2단계 판정 후 진행 여부.
- 한국 시장이 기본이다. 네이버·카카오·국내 커뮤니티를 먼저 보고, 해외는 비교용으로 본다.
- 웹 검색으로 못 여는 사이트는 "확인 불가"로 적는다. 크롬 연동(`claude --chrome`)이 있으면 경쟁사 화면을 직접 열어 본다.

## 0단계: 입력 정리

아이디어에서 아래 4개를 뽑는다. 빠진 게 있으면 **한 번에 모아서** 최대 3개만 묻는다. 사용자가 "알아서"라고 하면 합리적으로 가정하고 `[가정]`으로 표시한다.
- 누가 쓰나 (타깃)
- 어떤 불편을 없애나
- 어떻게 돈을 받나 (구독, 건당, 광고, 수수료)
- 목표 수익: 기본값 **월 순수익 300만 원** (1인 개발자가 계속할 가치가 있는 최소선으로 가정)

`<slug>`는 아이디어를 영문 소문자·하이픈으로 줄인 이름이다.

## 1단계: 문제·고객 정의 (약 5분)

- 타깃 1명을 구체적으로: 직업·상황·그 불편을 겪는 순간
- 지금 쓰는 대안(엑셀, 외주, 경쟁 앱, 참고 견딤)과 그 대안의 비용
- **불편의 근거** 원문 3개 이상: 커뮤니티 글·리뷰·질문 링크와 인용

## 2단계: 조기 중단 검토 ← 가장 중요

조사를 더 하기 전에 **돈과 필요성**으로 먼저 거른다. 템플릿의 채점표를 채운다.

**A. 필요성 (굳이 필요한가)**
1. 없으면 사람들이 **실제로 손해를 보나**, 아니면 있으면 좋은 정도인가
2. 지금 대안으로 **충분히 해결되고 있지 않나**
3. 대기업 무료 기능이나 ChatGPT·Claude에 한 줄 물어보는 것으로 **대체되지 않나**
4. 1단계 근거가 **서로 다른 곳에서 반복**되나, 한두 명의 불만인가

**B. 수익성 (돈이 되나)**
1. 비슷한 제품이 **실제로 돈을 받고 있나** → 경쟁사 가격표 링크로 확인
2. 목표 수익에 필요한 유료 고객 수를 계산한다: `필요 고객 수 = 목표 월 수익 ÷ (예상 월 가격 × (1 − 결제 수수료·비용 비율))`. 비용 비율은 모르면 30%로 둔다
3. 그 고객 수를 **1인이 1년 안에 모을 수 있나**: 타깃 규모, 도달 채널 기준
4. 돈을 내는 사람과 쓰는 사람이 같나. 다르면 영업이 필요해 1인에게 불리하다

**점수와 판정** (각 항목 1~5점)
- **즉시 중단:** 필요성 평균 ≤ 2 **또는** 수익성 평균 ≤ 2 **또는** B-2 계산 결과가 1년 안에 불가능
- **수정 후 진행:** 둘 다 2 초과 3 미만 → 타깃이나 수익 방식을 바꾼 대안 1~2개 제시
- **진행:** 둘 다 3 이상

**중단이면 여기서 끝낸다.** 파일에 0·1·2단계와 "살릴 수 있는 방향" 1~2개만 쓰고, 사용자에게 판정과 이유 3줄을 보고한다.
**진행·수정이면** 판정을 한 줄로 알리고 사용자 확인을 한 번 받은 뒤 3단계로 간다.

## 3단계: 수요 신호

- 네이버 데이터랩·Google Trends 검색어 추이(최근 1~3년), 계절성
- 커뮤니티에서 같은 불편이 언급된 횟수와 최근성
- 결론 한 줄: 커지는 중 / 정체 / 줄어드는 중

## 4단계: 경쟁사·롤모델

- 직접 경쟁 3~5개, 롤모델(다른 분야지만 배울 제품) 1~2개
- **기능 비교표:** 행=기능, 열=제품, 칸=O/X/부분
- **가격표:** 무료 범위, 유료 가격, 과금 단위
- **리뷰 불만 Top 5:** 앱스토어·플레이스토어·G2 낮은 별점에서 원문 인용
- **빈칸:** 아무도 안 하거나 다들 못하는 것 → 우리 차별점 후보

## 5단계: 롤모델 UX 해부

롤모델·경쟁사 2~3개를 단계별로 분해한다. 크롬 연동이 있으면 직접 가입해 보고, 없으면 공개 스크린샷·리뷰 영상·Mobbin/Lazyweb 레퍼런스를 쓴다.
- 첫 화면에서 무엇을 약속하나(헤드라인 원문)
- 가입까지 클릭 수, 가입 방식
- 온보딩 질문 수와 내용
- **첫 가치 도달**까지 걸리는 클릭 수·시간
- 결제 화면이 처음 나오는 시점
- 따라 할 것 3개 / 피할 것 3개

## 6단계: 디자인 방향

- 분위기 키워드 3개, 참고 제품 2개, 색·글꼴 방향
- `design-router` 스킬에 그대로 넘길 수 있는 5줄 요약(brief)

## 7단계: 첫 출시 범위 — 짧은 기간, 많은 기능

AI 코딩을 전제로 **기간은 짧게, 기능은 넓게** 잡는다.
- 기간: 기본 **3주**(1인 + Claude Code 기준). 사용자가 다른 기간을 말하면 그걸 쓴다
- 기능을 4묶음으로 나눠 **최대한 첫 출시에 넣는다**
  1. 핵심 경험: 첫 가치를 만드는 기능
  2. 차별점: 4단계 빈칸을 채우는 기능
  3. 편의: 저장·검색·알림·다크모드 등 경쟁사 대비 빠지면 티 나는 것
  4. 성장 장치: 공유·초대·결과물 내보내기·워터마크 등 알려지게 만드는 것
- 기능마다 예상 작업일(AI 코딩 기준)을 적고, 합계가 기간을 넘으면 **성장 장치 → 편의** 순으로 "2차 출시"로 넘긴다
- 규칙: 기능이 늘어도 **첫 가치까지의 클릭 수는 늘리지 않는다.** 추가 기능은 첫 가치 이후에 노출한다
- "안 함"은 핵심 흐름과 충돌하는 것만 적는다

## 8단계: 유저 플로우 — 화면 단위로 구체적으로

개발자가 이 섹션만 보고 화면을 만들 수 있을 만큼 구체적으로 쓴다.

1. **전체 흐름도:** mermaid `flowchart`로 화면 ID와 분기를 그린다
2. **여정 단계별 목표 시간**
   - 첫 방문 → 가입: 30초 이내
   - 가입 → 첫 가치: 2분 이내(제품 특성상 불가능하면 이유 명시)
   - 재방문 계기, 결제 전환 시점, 공유 시점, 해지 흐름
3. **화면 명세:** 모든 화면을 템플릿의 "화면 카드" 형식으로 쓴다. 빠뜨리면 안 되는 칸:
   - 진입 경로, 이 화면의 목적(사용자가 얻는 것 한 줄)
   - 위→아래 순서의 UI 요소
   - **실제 문구**(헤드라인, 버튼, 안내 문구를 그대로 쓸 수 있게)
   - 사용자 행동 → 시스템 반응 → 다음 화면
   - 빈 상태, 로딩, 오류, 권한 거부 상태의 화면과 문구
   - 이탈 방지 장치(진행률, 저장, 되돌리기)
   - 측정 이벤트 이름(예: `onboarding_step2_done`)
4. **꼭 포함할 화면:** 랜딩, 가입/로그인, 온보딩 각 단계, 첫 가치 화면, 핵심 반복 화면, 결과 공유, 알림 설정, 요금제·결제, 결제 완료, 설정, 해지
5. **엣지 케이스 표:** 네트워크 끊김, 결제 실패, 중복 가입, 무료 한도 도달, 데이터 0개일 때

## 9단계: 초반 입지 다지기와 인지도 전략

"첫 고객 몇 명"이 아니라 **이 분야에서 이름이 알려지는 방법**을 짠다.
1. **포지셔닝 한 문장:** "[타깃]을 위한 [카테고리]. [경쟁사]와 달리 [차별점]." 그리고 기억하기 쉬운 별칭("○○계의 ○○")
2. **선점할 자리:** 우리가 1등 할 수 있는 좁은 키워드·카테고리 1~2개(검색 경쟁이 약한 것, 3단계 데이터 근거)
3. **알려지게 만드는 장치(제품 안):** 공유하고 싶은 결과물, 공유 시 브랜드 노출, 초대 보상
4. **채널 전략:** 각 채널마다 무엇을, 얼마나 자주 올릴지
   - 만들면서 공개하기: X·스레드·링크드인·브런치 중 타깃이 있는 곳 1~2개
   - 국내 런칭: 디스콰이엇, 긱뉴스 Show GN, 타깃 커뮤니티(규칙 확인)
   - 해외 런칭(필요 시): Product Hunt, Hacker News Show HN, Reddit
   - 검색 유입: 무료 도구 페이지·비교 글·템플릿 배포
   - 협업: 타깃이 구독하는 뉴스레터·유튜버·인플루언서 5곳 후보(실제 링크)
5. **8주 캘린더:** 출시 전 4주(대기자 모으기, 개발 과정 공개) + 출시 후 4주(런칭, 후기 수집, 2차 런칭). 주차별 할 일 2~3개
6. **입지 지표:** 대기자 수, 팔로워, 브랜드 검색량, 커뮤니티 언급 수, 추천으로 들어온 가입 비율

## 10단계: 성공 지표와 출시 후 중단 기준

- 출시 후 4주·12주 목표: 가입자, 첫 가치 도달률, 유료 전환 건수, 월 매출
- **출시 후 중단 기준:** 2단계 수익 계산을 다시 해서, 12주 안에 목표 월 수익의 10%에 닿을 추세가 아니면 접거나 방향을 바꾼다. 숫자로 적는다
- 중단 시 남길 것: 코드·콘텐츠·대기자 명단을 다음 아이디어에 재활용하는 방법
